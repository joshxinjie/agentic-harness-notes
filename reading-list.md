# Reading list

Every source the notes use, grouped by the week that relies on it. Each source appears once, under the first week that needs it; the line says where else it helps. Start with the first one or two links in each week if you only have a little time.

## Week 1 — What an agent is

- [Anthropic — Building effective agents (Dec 2024)](https://www.anthropic.com/engineering/building-effective-agents) — The standard map of workflows versus agents, with the "simplest solution possible" rule and when an agent is worth it. Its Appendix 2, "Prompt engineering your tools", is the source for the agent-computer interface in 4.4 (ACI as much effort as HCI, poka-yoke, absolute file paths).
- [OpenAI — A practical guide to building agents (2025, PDF)](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf) — Three tests for when to build an agent; check the idea before committing; one agent before many.
- [Wang et al. — The Long-Horizon Task Mirage? Diagnosing Where and Why Agentic Systems Break (Apr 2026)](https://arxiv.org/html/2604.11978v1) — The HORIZON benchmark: success falls off a cliff as tasks get deeper, and planning and memory failures dominate long tasks. Evidence for the cost of autonomy, and background for Weeks 3 and 7.
- [Simon Willison — "An LLM agent runs tools in a loop to achieve a goal" (Sep 2025)](https://simonwillison.net/2025/Sep/18/agents/) — The one-line definition of an agent used throughout these notes.
- [Anthropic — Measuring AI agent autonomy in practice (Feb 2026)](https://www.anthropic.com/research/measuring-agent-autonomy) — Treats autonomy as a spectrum you can measure, not a yes-or-no.
- [Anthropic — How tool use works](https://platform.claude.com/docs/en/agents-and-tools/tool-use/how-tool-use-works) — The standard five-step tool loop and the message format.
- [Anthropic — Define tools](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools) — Tool schema fields, the 3–4-sentence description rule with good and poor examples, `tool_choice`, and how definitions end up in the system prompt. Also the basis for 4.2's description and parameter rules.
- [Anthropic — Stop reasons and fallback](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons) — Every `stop_reason` and what the harness should do about it, including `pause_turn`, a `max_tokens` cut-off mid tool call, and the empty `end_turn`. The main text behind 2.5.
- [Anthropic Engineering — Writing effective tools for AI agents, using AI agents (Sep 2025)](https://www.anthropic.com/engineering/writing-tools-for-agents) — Tools as a contract with an unpredictable caller: which tools to build, merging, namespacing, token efficiency (`response_format`, 72 vs 206 tokens), useful error responses, and letting a model improve descriptions against an eval. The main source for 4.2 and 4.3.
- [Thorsten Ball — How to Build an Agent (Apr 2025)](https://ampcode.com/notes/how-to-build-an-agent) — A code-editing agent in under 400 lines of Go; the clearest proof that the loop is simple.
- [SWE-agent team — mini-swe-agent](https://github.com/SWE-agent/mini-swe-agent) ([control flow docs](https://mini-swe-agent.com/latest/advanced/control_flow/)) — A ~100-line bash-only agent with linear history, step/cost/time limits and a submission string that scores over 74% on SWE-bench Verified. The reference "small loop, big score" example.
- [Edd Mann — Around the Loop: Building a Coding Agent Harness in Python (Apr 2026)](https://eddmann.com/posts/around-the-loop-building-a-coding-agent-harness-in-python/) — Goes from the bare loop to shaped tools, Pydantic-checked schemas, permission hooks and compaction; a good bridge from 1.5 to Weeks 3–5.
- [sanbuphy — nanoAgent](https://github.com/sanbuphy/nanoAgent) — "If you can read ~100 lines of Python, you understand agents": three tools and OpenAI function calling.
- [OpenAI — Harness engineering: leveraging Codex in an agent-first world (Feb 2026)](https://openai.com/index/harness-engineering/) — A production case study of harness over prompting: docs as the record, linters as guardrails, observability as feedback.
- [Anthropic Engineering — Effective harnesses for long-running agents (Nov 2025)](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) ([companion repo](https://github.com/anthropics/cwc-long-running-agents)) — Initializer and coding agents, the feature list, the progress file and the clean-state rule. Also the reference for upfront planning that spans sessions (2.3).
- [HumanLayer — Skill Issue: Harness Engineering for Coding Agents (Mar 2026)](https://www.humanlayer.dev/blog/skill-issue-harness-engineering-for-coding-agents) — The "model + harness" split and the list of things you can configure in a harness.

## Week 2 — Core mechanics

- [Anthropic Engineering — Effective context engineering for AI agents (Sep 2025)](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) — Attention budget, context rot, just-in-time retrieval, and compaction / note-taking / sub-agents for long tasks. The anchor text for 2.1 and all of Week 3, and its "system prompts" and "tools" sections anchor 4.1 and 4.2.
- [Chroma — Context Rot: How Increasing Input Tokens Impacts LLM Performance (Jul 2025)](https://www.trychroma.com/research/context-rot) — 18 models get worse as input grows, even on trivial tasks; question–fact similarity, distractors and layout all matter.
- [Anthropic — Context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows) — What counts toward the window, how it builds up, thinking-block handling per model, context awareness tags, and what happens on overflow.
- [Yao et al. — ReAct: Synergizing Reasoning and Acting in Language Models (2022)](https://arxiv.org/abs/2210.03629) — Where Thought/Action/Observation comes from; still the clearest case for why reasoning and acting need each other.
- [Anthropic — Thinking](https://platform.claude.com/docs/en/build-with-claude/thinking) (companions: [Adaptive thinking](https://platform.claude.com/docs/en/build-with-claude/adaptive-thinking), [Extended thinking](https://platform.claude.com/docs/en/build-with-claude/extended-thinking)) — Thinking modes, interleaved thinking, the pass-blocks-back rule, signatures and redacted_thinking, and caching effects; the companions cover effort levels and manual budgets.
- [Anthropic Engineering — The "think" tool (Mar 2025)](https://www.anthropic.com/engineering/claude-think-tool) — A do-nothing tool used as a mid-run scratchpad, with τ-bench numbers and when it beats built-in thinking.
- [LangChain — Plan-and-Execute Agents (Feb 2024)](https://www.langchain.com/blog/planning-agents) — Planner / executor / replanner, the speed–cost–quality case against ReAct, and the ReWOO and LLMCompiler variants. Older, but still the clearest statement of the pattern.
- [Claude Code docs — Best practices, "Explore first, then plan, then code"](https://code.claude.com/docs/en/best-practices) — Plan mode as a read-only phase, the four-phase workflow, when to skip planning, and checking the diff against PLAN.md.
- [Anthropic — Structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs) — JSON outputs versus strict tool use, the supported schema subset, grammar scope and caching, complexity limits, and the refusal / `max_tokens` / enum-casing caveats.
- [Anthropic — Strict tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/strict-tool-use) — What `strict: true` guarantees (input shape, a valid tool name) and which toolsets refuse it.
- [OpenAI — Structured model outputs](https://developers.openai.com/api/docs/guides/structured-outputs) — JSON mode versus Structured Outputs, the `strict` rules, detectable refusals; and a reminder that fitting the schema is not the same as being correct.
- [OpenHands — Stuck Detector](https://docs.openhands.dev/sdk/guides/agent-stuck-detector) — The five stuck patterns with their thresholds, compared by meaning and ignoring ids. The reference loop detector.
- [Claude Agent SDK — How the agent loop works](https://code.claude.com/docs/en/agent-sdk/agent-loop) — Turns versus messages, `max_turns` and `max_budget_usd`, result subtypes, the `Stop` hook and automatic compaction. Also useful for 3.2 and 3.5.
- [OpenAI Agents SDK — Running agents](https://openai.github.io/openai-agents-python/running_agents/) — When the loop counts output as final, and `max_turns` (default 10) with `MaxTurnsExceeded`.
- [Anthropic — Errors](https://platform.claude.com/docs/en/api/errors) — Every HTTP status, which ones are temporary, the `retry-after` header (and the spend-cap 429 without it), SDK retries and `request_id`. The reference for what to retry.
- [Anthropic — Python SDK](https://platform.claude.com/docs/en/api/sdks/python) — Exception classes per status code, `max_retries` (default 2), the 10-minute default timeout and `APITimeoutError`, and per-request overrides.
- [Anthropic — Handle tool calls](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls) — The `is_error` format, "write instructive error messages", and the model's retry-with-corrections behaviour. Also the basis for 4.3.
- [AWS Architecture Blog — Exponential Backoff and Jitter (Marc Brooker, 2015)](https://aws.amazon.com/blogs/architecture/exponential-backoff-and-jitter/) — Why backoff alone bunches retries together, and how full jitter cuts calls by more than half with 100 competing clients. Applies to any fleet of agents sharing an API quota.
- [OpenAI Agents SDK — Tools, "Handling errors in function tools"](https://openai.github.io/openai-agents-python/tools/) — `failure_error_function` (by default tells the model an error happened; `None` re-raises) and `ModelBehaviorError` for invalid tool JSON.

## Week 3 — State and memory

- [LangChain docs — Memory overview](https://docs.langchain.com/oss/python/concepts/memory) — Short-term versus long-term memory, semantic / episodic / procedural, and hot-path versus background writes. The cleanest taxonomy.
- [Anthropic — Memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool) — `memory_20250818`, its six commands, the client-side handler, the injected memory protocol and path-traversal checks.
- [Anthropic Cookbook — Memory tool notebook](https://github.com/anthropics/claude-cookbooks/blob/main/tool_use/memory_cookbook.ipynb) — A runnable `/memories` handler and a demo across sessions.
- [Claude Code docs — How Claude remembers your project](https://code.claude.com/docs/en/memory) — CLAUDE.md versus auto memory, the under-200-lines rule, `@path` imports, `.claude/rules/`, the `MEMORY.md` index and its 200-line / 25 KB limit, memory types and the `modified` timestamp. The reference for memory as documents.
- [Letta — Memory Blocks: The Key to Agentic Context Management](https://www.letta.com/blog/memory-blocks/) — Size-limited blocks put into every prompt and edited by the agent, shared blocks and sleep-time agents, and the case for curating memory over retrieving it.
- [Anthropic — Compaction](https://platform.claude.com/docs/en/build-with-claude/compaction) — `compact_20260112`, trigger defaults, the `compaction` block, `instructions`, `pause_after_compaction`, `usage.iterations` billing and what gets lost.
- [Anthropic — Context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing) — `clear_tool_uses_20250919` and `clear_thinking_20251015` with every setting and default, `applied_edits`, and cache effects.
- [Anthropic Cookbook — Context engineering: memory, compaction, and tool clearing](https://platform.claude.com/cookbook/tool-use-context-engineering-context-engineering-tools) — A runnable version of all three mechanisms together.
- [Claude Code docs — Explore the context window](https://code.claude.com/docs/en/context-window) — What loads at startup, what each read costs, and the table of what survives compaction (the 5-file / 5,000-token / 25,000-token caps).
- [Manus (Yichao Ji) — Context Engineering for AI Agents: Lessons from Building Manus (Jul 2025)](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus) — Design around the KV cache, the file system as restorable context, recitation via `todo.md`, and keeping mistakes in. The best practitioner write-up on context management; also the source for 4.6 (100:1 input:output, append-only, "mask, don't remove").
- [Sen et al. — Is Grep All You Need? How Agent Harnesses Reshape Agentic Search (May 2026)](https://arxiv.org/abs/2605.15184) — Grep versus vector search across four coding harnesses; the harness moves accuracy more than the searcher (93.1% vs 76.7%, same model and data).
- [Anthropic Engineering — Contextual Retrieval (Sep 2024)](https://www.anthropic.com/engineering/contextual-retrieval) — Contextual embeddings + BM25 + reranking (67% fewer retrieval failures) and the 200k-token "just put it in the prompt" rule. The reference for pre-retrieval done well.
- [LlamaIndex — Is grep all you need? Lexical vs semantic search for agents (May 2026)](https://www.llamaindex.ai/blog/is-grep-all-you-need-lexical-vs-sematic-search-for-agents) — The case for an index behind the search tool at scale: scan cost, unstructured files, vocabulary mismatch.
- [Singh et al. — Agentic Retrieval-Augmented Generation: A Survey on Agentic RAG (Jan 2025, rev. Apr 2026)](https://arxiv.org/abs/2501.09136) — A taxonomy of agentic RAG designs; useful words, less useful as engineering advice.
- [LangGraph docs — Checkpointers](https://docs.langchain.com/oss/python/langgraph/checkpointers) (companion: [Durable execution](https://docs.langchain.com/oss/python/langgraph/durable-execution)) — Checkpoints per super-step, `StateSnapshot`, `thread_id`, replay and `update_state`, pending writes; the companion covers durability modes, `@task` and idempotency.
- [Claude Agent SDK docs — Work with sessions](https://code.claude.com/docs/en/agent-sdk/sessions) — Sessions as `.jsonl` transcripts on disk, `resume` / `continue_conversation` / `fork_session`, and "sessions persist the conversation, not the filesystem".
- [Diagrid (Yaron Schneider) — Checkpoints are not durable execution (Feb 2026)](https://www.diagrid.io/blog/checkpoints-are-not-durable-execution-why-langgraph-crewai-google-adk-and-others-fall-short-for-production-agent-workflows) — What checkpointing lacks (supervisor, watchdog, protection from duplicate runs) and what a durable runtime adds. A vendor's argument, but the distinction is sound.
- [Vadim — Durable execution in LangGraph: agents that survive failure and resume where they left off (Jun 2026)](https://vadim.blog/durable-execution-agents-that-survive-failure-and-resume-where-they-left-off) — A practical walk-through of `thread_id`, the three durability modes, and idempotency guards (no `now()` in steps).
- [Anthropic Engineering — How we built our multi-agent research system (Jun 2025)](https://www.anthropic.com/engineering/multi-agent-research-system) — Lead agent plus sub-agents in separate context windows, token costs (~4× / ~15×), the 90.2% result, effort-scaling rules and early failures. The main source for 3.6; also for 5.6 (parallel work cut research time by up to 90%).
- [Claude Code docs — Subagents](https://code.claude.com/docs/en/sub-agents) — The reference implementation: own context window, summary-only return, frontmatter fields, built-in Explore / Plan / general-purpose, no nested spawning.
- [Cognition (Walden Yan) — Don't Build Multi-Agents (Jun 2025)](https://cognition.ai/blog/dont-build-multi-agents) — The case against parallel sub-agents that act ("actions carry implicit decisions"); where the read-heavy versus write-heavy split comes from.
- [LangChain — How and when to build multi-agent systems (Jun 2025)](https://www.langchain.com/blog/how-and-when-to-build-multi-agent-systems) — Brings Anthropic's and Cognition's views together: breadth-first versus sequential tasks, read versus write, and task descriptions as the top job.

## Week 4 — Prompt and tool design

- [Drew Breunig — How Claude Code builds a system prompt (Apr 2026)](https://www.dbreunig.com/2026/04/04/how-claude-code-builds-a-system-prompt.html) — The ~25 conditional parts in order, the cache boundary marker, and which parts are fixed versus recomputed each turn. The reference for prompt assembly.
- [Piebald-AI — claude-code-system-prompts (v2.1.259, Sep 2026)](https://github.com/Piebald-AI/claude-code-system-prompts) — Every system-prompt section and all 27 built-in tool descriptions pulled from the shipped source. - [OpenAI — Function calling guide, best practices](https://developers.openai.com/api/docs/guides/function-calling) — Clear names, enums to block invalid states, don't make the model fill known values, merge always-sequential functions, keep the tool count small.
- [Model Context Protocol specification — Tools, "Error handling" (2025-06-18)](https://modelcontextprotocol.io/specification/2025-06-18/server/tools) — The split between protocol errors and tool execution errors, with `isError: true` in a normal result; also its security section.
- [Alpic — Better MCP tool call error responses: help your AI recover gracefully (Jul 2025)](https://alpic.ai/blog/better-mcp-tool-call-error-responses-ai-recover-gracefully) — Three worked patterns for error messages that teach the model, set against "An error occurred." Short; read it for the examples.
- [Yang et al. — SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering (NeurIPS 2024)](https://proceedings.neurips.cc/paper_files/paper/2024/file/5a7c947568c1b1328ccc5230172e1e7c-Paper-Conference.pdf) ([arXiv](https://arxiv.org/abs/2405.15793)) — Where the ACI term comes from: four design principles and the ablation table (11.0% → 18.0%; window sizes; search styles; linter).
- [SWE-agent docs — ACI background](https://github.com/SWE-agent/SWE-agent/blob/main/docs/background/aci.md) — The short version: linter on edit, 100-line viewer, short search results, explicit empty-output message.
- [Anthropic — Raising the bar on SWE-bench Verified with Claude 3.5 Sonnet (Jan 2025)](https://www.anthropic.com/news/swe-bench-sonnet) — The minimal bash + string-replace scaffold (49%); a worked example of exact-string edits and absolute paths.
- [Anthropic Engineering — Equipping agents for the real world with Agent Skills (Oct 2025)](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills) — Why skills exist: onboarding guides, progressive disclosure, code inside skills, security caveats.
- [Agent Skills — Specification (Dec 2025)](https://agentskills.io/specification) — The vendor-neutral `SKILL.md` format: fields and limits, folders, the three loading levels, the 500-line rule.
- [Claude docs — Agent Skills overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview) — Token cost per level, field limits, where skills work, runtime limits and security.
- [Claude docs — Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) — Keep it short, degrees of freedom (the bridge analogy), third-person descriptions, eval-driven writing, anti-patterns.
- [Claude Code docs — Skills](https://code.claude.com/docs/en/skills) — The reference harness implementation: locations, full frontmatter, the 1,536-character listing cut-off, and the 5k/25k re-attach budget after compaction.
- [Simon Willison — Agent Skills (Dec 2025)](https://simonwillison.net/2025/Dec/19/agent-skills/) — The open-standard launch and early adopters; notes the spec is deliberately small and loose.
- [Claude docs — Prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) — Automatic versus explicit breakpoints (max 4), the tools → system → messages order and what breaks it, TTLs and prices, minimum lengths, usage fields, pre-warming.
- [Claude blog — Lessons from building Claude Code: Prompt caching is everything (Thariq Shihipar, Apr 2026)](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything) — Fixed content first, never change tools mid-session, modes as tools, `defer_loading`, `<system-reminder>` updates, and alerting on cache breaks.
- [Claude Code docs — How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching) — How the reference harness uses the cache.

## Week 6 — Evaluation

- [Anthropic Engineering — Demystifying evals for AI agents (Jan 2026)](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) — The core vocabulary (task, trial, grader, transcript, outcome, eval harness), pass@k versus pass^k and environment isolation. Also the source for 6.2 (20–50 tasks from real failures, reference solutions, capability vs regression), 6.3 (grader families, isolated judges, Unknown option, scoring) and 6.4 (turn, tool-call and token metrics).
- [Yao et al. — τ-bench: A Benchmark for Tool-Agent-User Interaction in Real-World Domains (2024)](https://arxiv.org/abs/2406.12045) — Simulated user + tools + policy, graded on final database state, and the pass^k reliability metric.
- [Hamel Husain & Shreya Shankar — Q: How many examples do I need for an eval? (Sep 2026)](https://hamel.dev/blog/posts/evals-faq/how-many-examples-do-i-need-for-an-eval.html) — Error discovery over at least 100 traces (first 30 by hand), theoretical saturation, and growing eval sets from confirmed failures.
- [Hamel Husain — Using LLM-as-a-Judge for Evaluation: A Complete Guide (updated Sep 2026)](https://hamel.dev/blog/posts/llm-judge/) — Pass/fail with critiques, TPR/TNR instead of raw agreement, and train/dev/test splits for judge prompts.
- [Zheng et al. — Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena (2023)](https://arxiv.org/abs/2306.05685) — Position, verbosity and self-enhancement bias; strong judges agree with people over 80% of the time, about as often as people agree with each other.
- [Chen et al. — Evaluating Large Language Models Trained on Code (2021)](https://arxiv.org/abs/2107.03374) — The unbiased pass@k estimator and why sampling n > k lowers variance.
- [LangChain — agentevals](https://github.com/langchain-ai/agentevals) — Trajectory match modes (strict / unordered / subset / superset), per-tool argument matching, trajectory LLM-as-judge.
- [Kapoor et al. — AI Agents That Matter (2024)](https://arxiv.org/abs/2407.01502) — Measuring accuracy alone produces expensive agents; optimise cost and accuracy together.
- [Anthropic — A statistical approach to model evaluations (Nov 2024)](https://www.anthropic.com/research/statistical-approach-to-model-evals) — Standard errors and confidence intervals, clustered SEs (over 3× naive), paired differences and power analysis.
- [Anthropic Engineering — Quantifying infrastructure noise in agentic coding evals (Feb 2026)](https://www.anthropic.com/engineering/infrastructure-noise) — A 6-point Terminal-Bench 2.0 swing from resource settings alone, infra errors 5.8% → 0.5%, and doubt gaps under 3 points.
- [OpenAI — Why we no longer evaluate SWE-bench Verified (Feb 2026)](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/) — An audit of 138 hard problems (59.4% with flawed tests), gold patches reproduced word for word, saturation, and the move to SWE-bench Pro.

## Week 7 — Evaluation II and iteration

- [Zhang et al. — Which Agent Causes Task Failures and When? (Who&When, ICML 2025)](https://arxiv.org/abs/2505.00212) — Defines the decisive error step, and shows how hard it is to find automatically (53.5% for the agent, 14.2% for the step).
- [Langfuse — Error analysis to evaluate LLM applications](https://langfuse.com/blog/2025-08-29-error-analysis-to-evaluate-llm-applications) — A practical walk-through of reading traces and writing down what went wrong, before building evals.

- [Zhu et al. — Where LLM Agents Fail and How They Can Learn from Failures (AgentErrorTaxonomy / AgentDebug, 2025)](https://arxiv.org/abs/2509.25370) — A module-by-module error taxonomy for single agents, and re-running from the earliest decisive error.
- [Hamel Husain — Why is error analysis so important, and how is it performed?](https://hamel.dev/blog/posts/evals-faq/why-is-error-analysis-so-important-in-llm-evals-and-how-is-it-performed.html) — Open coding, then axial coding ("the most important step"), then counting, until saturation.
